# Как посмотреть и использовать проект

Проект готов как локальный продукт и пакет для GitHub. Исходные токены, Google-ключ, реальные записи и полный диплом в публичную версию не включены.

## 1. Посмотреть без установки

Открой **OPEN_DEMO.html** двойным щелчком. В нём можно посмотреть запросы, назначить сотрудника, изменить статус, открыть историю и аналитику. Всё на английском. Данные вымышленные; после обновления страницы изменения исчезают. Это интерактивный preview, а не сервер с базой.

## 2. Что лежит внутри

- `app/` — новый Python-код бота, веб-панели, базы и аналитики.
- `tests/` — проверки поведения, безопасности, сохранения, SQL и обработчиков бота.
- `analytics/` — SQL-запросы для метрик.
- `docs/` — английские PRD, BRD, требования, истории, процессы, исследования и материалы для резюме.
- `docs/diagrams/` — архитектура и семь редактируемых UML-диаграмм.
- `docs/screenshots/` — скриншоты настоящей веб-панели.
- `.github/workflows/` — автоматические проверки для GitHub.
- `README.md` — главная страница будущего репозитория.

## 3. Запустить полноценную версию на Windows

Установи Python 3.12, распакуй архив и открой терминал внутри папки проекта. Команды можно копировать по одной:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m app.cli seed
.venv\Scripts\python.exe -m uvicorn app.web:create_app --factory --host 127.0.0.1 --port 8000
```

Открой **http://127.0.0.1:8000**. Логин `demo`, пароль `PortfolioDemo2026!`. База сохраняет изменения. Для просмотра роли аналитика — логин `analyst`, для сотрудника housekeeping — `housekeeping-agent`, пароль тот же. Терминал должен оставаться открытым; Ctrl+C останавливает сервер.

Бот — отдельный процесс. Для него нужен новый токен, который нельзя публиковать. Подробные шаги: `docs/setup.md`.

## 4. Сначала заменить старые ключи

В исходном архиве сохранены Telegram-токен и приватный ключ Google. В BotFather нужно отозвать старый токен; в Google Cloud — отключить/удалить старый ключ сервисного аккаунта. Только удаление файлов из GitHub не обезвреживает ключи. Я не использовала их и не выполняла отзыв через твои аккаунты.

## 5. Публикация

Имя репозитория — **hotel-guest-experience-platform**, владелец репозитория — **alyalbina**. Публичный репозиторий создан. Загрузка файлов и публикация демо проверяются отдельно. После загрузки включается GitHub Pages для ветки `main` и папки `/docs`: там лежит бесплатный preview на синтетических данных. Подробности: `docs/publishing.md`.

Нельзя загружать исходный ZIP, `.env`, `credits.json`, локальную базу, `.venv` и полный диплом. В готовом чистом архиве их нет.

## 6. Как рассказывать работодателю

В 2024 году — дипломное исследование и прототип; в 2026 — восстановление и расширение для портфолио. В дипломе указаны 182 анкеты, но исходные ответы не сохранились. Подтверждённого улучшения времени сервиса, CSAT или выручки нет. Такие результаты нельзя добавлять в резюме как достижения.

В оригинальном боте указан другой разработчик. В README сохранена атрибуция, а новый код явно отмечен как восстановленный с ИИ-помощью. Готовые формулировки для CV, LinkedIn и интервью — в `docs/portfolio.md`. Выбирай акцент под BA, Product Analyst или PM.
